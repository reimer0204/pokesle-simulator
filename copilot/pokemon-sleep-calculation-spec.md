# ポケモンスリープ計算仕様

この文書は、本リポジトリが現在採用しているポケモンスリープ関連の計算式を、調査・実装時に短時間で参照できるよう整理したものです。

## 1. 文書の位置付け

- 公式に公開された全仕様を記録した文書ではなく、主に現在のソースコードから確認できるシミュレーター内の計算仕様です。
- ユーザーから明示された仕様が本文書と異なる場合は、ユーザーの仕様を優先します。
- 本文書と実装が異なる場合は、意図的な変更か記載漏れかを確認します。計算仕様を変更した場合は、原則として実装と本文書を同時に更新します。
- マスター値は `src/data/`、計算処理は `src/models/simulation/` を最終的な確認先とします。
- 確率は、特記がなければ `0.05 = 5%` のように0～1で扱います。
- 時間は、特記がなければ秒単位です。

主な参照元は次のとおりです。

- ポケモンマスター: `src/data/pokemon.ts`
- きのみマスター: `src/data/berry.ts`
- 食材・料理マスター: `src/data/food_and_cooking.ts`
- メインスキルマスター: `src/data/skill.ts`
- 性格マスター: `src/data/nature.ts`
- ポケモンの主要計算: `src/models/simulation/pokemon-simulator.ts`
- げんきとおてつだい倍率: `src/models/help-rate.ts`
- チーム・料理・スコア計算: `src/models/simulation/team-simulator.ts`
- 厳選度・パーセンタイル: `src/models/simulation/evaluate-simulator.ts`
- レベル上げ: `src/data/exp.ts`

## 2. レベルと有効なサブスキル

サブスキルは並び順に、次のレベルで1つずつ有効になります。

| 順番 | 解放レベル |
| ---: | ---: |
| 1 | 10 |
| 2 | 25 |
| 3 | 50 |
| 4 | 70 |
| 5 | 80 |

計算には、現在レベルで有効になっている先頭からのサブスキルだけを使用します。

## 3. ゲーム週・料理カテゴリ・食材バッグ

ゲーム内の週は月曜日に切り替わる。週の切り替え時には、その週に稼いだフィールドエナジーが0へリセットされ、好みのきのみと料理カテゴリが改めて抽選される。

- 料理カテゴリは「カレー／シチュー」「サラダ」「デザート／ドリンク」のいずれか1種類である。週ごとに選ばれたカテゴリに属する料理だけを作成でき、他の2カテゴリのレシピは作成できない。
- 食材バッグには容量上限がある。食材は無制限には保持できないため、食材の獲得量・料理の作成可否・週をまたぐ計画を扱う処理では、バッグ容量と現在の所持数を考慮する。
- 週替わりの抽選結果や食材バッグの挙動をシミュレーションへ導入・変更する場合は、日ごとの期待値だけで完結させず、週の開始時点と容量到達時の扱いを明示する。

## 4. 食材構成と食材数

### 4.1 各枠で選択できる食材

`pokemon.ts` の `foodList` を `[A, B, C]` とすると、通常の食材構成は次の6通りです。

- `AAA`
- `AAB`
- `AAC`
- `ABA`
- `ABB`
- `ABC`

したがって、各枠の候補は次のとおりです。

| 枠 | 解放レベル | 選択候補 |
| ---: | ---: | --- |
| 1枠目 | 初期 | Aのみ |
| 2枠目 | 30 | AまたはB |
| 3枠目 | 60 | A、B、C |

レベルによる使用枠数は、Lv1～29が1枠、Lv30～59が2枠、Lv60以上が3枠です。

ミュウやダークライのように `foodList` が4種類以上ある特殊なポケモンは、`pokemon.ts` で全食材に各枠の個数が設定されます。通常の6構成を前提にせず、その機能で食材候補を選ぶ処理も合わせて確認してください。

### 4.2 1回のおてつだいで獲得する食材数

まず、1枠目の食材エナジーを基準値に変換します。

```text
基準食材エナジー = Aの基礎エナジー × とくい補正
とくい補正 = 食材とくいまたはオールなら2、それ以外は1
```

各枠の食材数は次の式で四捨五入します。

```text
食材数 = round(基準食材エナジー × 枠係数 ÷ 選択食材の基礎エナジー)
枠係数 = [1, 2.25, 3.6]
```

イベントの食材数加算やEXモードの加算は、この基礎個数を求めた後に適用します。

## 5. きのみ

### 5.1 きのみ1個のエナジー

```text
レベル補正後エナジー = max(
  基礎エナジー + レベル - 1,
  基礎エナジー × 1.025 ^ (レベル - 1)
)

最終きのみエナジー =
  レベル補正後エナジー × フィールド倍率 ÷ 100 × 設定上のきのみ評価倍率
```

通常、好みではないきのみのフィールド倍率は100、好みのきのみは200です。EXフィールドの設定によっては240を使用します。

### 5.2 1回のおてつだいで獲得する個数

```text
きのみ数 = とくい基礎数 + きのみの数S + イベント加算
とくい基礎数 = きのみとくいまたはオールなら2、それ以外は1
きのみの数S = 有効なら1、それ以外は0
```

## 6. 食材確率と1回あたりの期待値

### 6.1 食材確率

```text
食材確率 = マスター食材確率
  × (1 + 食材確率アップS + 食材確率アップM)
  × 性格補正

食材確率アップS = 0.18
食材確率アップM = 0.36
性格補正 = 上昇1.2、下降0.8、補正なし1
```

### 6.2 食材数・食材エナジー

解放済み各枠が等確率で選ばれる前提です。

```text
平均食材数 = 各枠の食材数の合計 ÷ 解放済み枠数

食材エナジー/手伝い =
  Σ(各枠の評価用食材エナジー × 各枠の食材数)
  ÷ 解放済み枠数
  × 設定上の食材評価倍率
```

きのみか食材のどちらかを得る1回のおてつだいの期待値は、次の加重平均です。

```text
取得エナジー/手伝い =
  きのみエナジー/手伝い × (1 - 食材確率)
  + 食材エナジー/手伝い × 食材確率
```

## 7. 最大所持数

### 7.1 基本式

```text
所持数 = マスター所持数
  + 最大所持数アップSの6
  + 最大所持数アップMの12
  + 最大所持数アップLの18
  + 睡眠リボン加算
```

睡眠時間による加算は累積します。

| 累計睡眠時間 | その段階での加算 | 累計加算 |
| ---: | ---: | ---: |
| 200時間以上 | +1 | +1 |
| 500時間以上 | +2 | +3 |
| 1000時間以上 | +3 | +6 |
| 2000時間以上 | +2 | +8 |

その後、チームシミュレーションではイベント加算・イベント倍率、キャンプチケットの1.2倍、EX補正の順に適用し、最後に切り上げます。キャンプチケットを掛けた直後には一度切り捨てています。

### 7.2 いつのまに育成へ移る目安

```text
平均取得個数/手伝い =
  きのみ数 × (1 - 食材確率) + 平均食材数 × 食材確率

所持上限到達手伝い数 =
  max(所持数 ÷ 平均取得個数/手伝い + 4, 0)
```

末尾の4回はキュー消化分として加えています。

## 8. メインスキル

### 8.1 スキルレベル

通常の初期値は進化段階 `evolveLv` です。そこへ有効なサブスキルを加算します。

```text
スキルレベル = 初期スキルレベル
  + スキルレベルアップSの1
  + スキルレベルアップMの2
  + イベント・EX補正
```

最終的に1以上、対象スキルの効果配列の長さ以下へ制限します。

### 8.2 基礎発生確率

```text
スキル確率 = マスタースキル確率
  × (1 + スキル確率アップS + スキル確率アップM)
  × 性格補正
  × イベント・EX補正

スキル確率アップS = 0.18
スキル確率アップM = 0.36
性格補正 = 上昇1.2、下降0.8、補正なし1
```

### 8.3 天井を平均化した確率

天井回数は次の値を使用します。

```text
スキルとくい・オール = 40 × 3600 ÷ マスターおてつだい時間
それ以外 = 78
```

天井を平均化した1抽選あたりの確率は次の式です。

```text
補正スキル確率 =
  スキル確率 ÷ (1 - (1 - スキル確率) ^ 天井回数)
```

## 9. おてつだい時間

### 9.1 速度短縮量

```text
速度短縮量 =
  おてつだいスピードSの0.07
  + おてつだいスピードMの0.14
  + おてつだいボーナス対象数 × 0.05

速度短縮量の上限 = 0.35
```

シミュレーションでは、チームから受ける分も含む `helpBonus` を渡します。ゲームの個体詳細画面に表示される時間を推定する場合は、自身の「おてつだいボーナス」を含めません。

### 9.2 基本のおてつだい時間

```text
基本時間 = floor(
  マスターおてつだい時間
  × (1 - (レベル - 1) × 0.002)
  × (1 - 速度短縮量)
  × 性格補正
  ÷ キャンプ補正
)

性格補正 = 上昇0.9、下降1.075、補正なし1
キャンプ補正 = チケット使用時1.2、それ以外1
```

短いほど速い値なので、上昇性格は0.9倍になります。

### 9.3 睡眠リボンによる速度補正

最終進化まで残り1段階の場合は、500時間以上で0.95倍、2000時間以上でさらに0.88倍します。残り2段階の場合は、500時間以上で0.89倍、2000時間以上でさらに0.75倍します。

2000時間以上では両方の条件が成立するため、コード上は各倍率を累積して適用します。その後、必要に応じてEXフィールド補正を掛けます。

### 9.4 画面表示値との端数差

ゲーム画面とマスター値・シミュレーターの式の間で、1秒程度の差が生じる例があります。OCR補正では、計算値との差が3秒以内なら認識した画面表示を保持します。表示値を厳密に再現する処理では、この差を無視して計算値へ上書きしないでください。

## 10. げんきとおてつだい回数

### 10.1 起床時の回復量

```text
起床時回復量 = min(
  min(睡眠時間 ÷ 8.5, 1) × 100
  × 性格のげんき回復補正
  × (1 + げんき回復ボーナス数 × 0.14),
  100
)

性格補正 = 上昇1.2、下降0.88、補正なし1
```

### 10.2 げんきによる速度変化

`HelpRate` はげんきの減少、確認時刻、回復スキルを時系列で処理します。げんきは600秒で1減少し、区間ごとの実おてつだい時間を次の倍率で計算します。

| げんき | おてつだい時間へ掛ける倍率 |
| --- | ---: |
| 80超 | 0.45 |
| 60超～80以下 | 0.52 |
| 40超～60以下 | 0.58 |
| 0超～40以下 | 0.66 |
| 0 | 1.00 |

`genkiFull` を指定した近似では、昼・夜のおてつだい回数倍率をともに2.22として扱います。

### 10.3 昼・夜のおてつだい回数

```text
昼時間 = 86400 - round(睡眠時間 × 3600)
夜時間 = round(睡眠時間 × 3600)

昼手伝い数 = 昼時間 ÷ おてつだい時間 × 昼げんき倍率
夜手伝い数 = 夜時間 ÷ おてつだい時間 × 夜げんき倍率
```

日中は確認回数ごと、夜間は睡眠全体について所持上限までを通常取得とし、超過分をいつのまに育成として扱います。いつのまに育成では食材を取得せず、きのみだけを取得します。

## 11. 1日あたりの取得エナジー

通常期待値の場合は次の式です。

```text
通常食材抽選数 = 通常手伝い数 × 食材確率
通常きのみ抽選数 = 通常手伝い数 × (1 - 食材確率)
きのみ抽選数 = 通常きのみ抽選数 + いつのまに育成手伝い数

きのみエナジー/日 = きのみエナジー/手伝い × きのみ抽選数
食材エナジー/日 = 食材エナジー/手伝い × 通常食材抽選数
取得エナジー/日 = きのみエナジー/日 + 食材エナジー/日
```

下振れ基準を使用する場合は、単純な積ではなく `ProbBorder` から得た境界値で食材数を計算します。

最終的なポケモンの日給は次のとおりです。

```text
エナジー/日 = 取得エナジー/日 + スキルエナジー/日
スキルエナジー/日 = 1回あたりのスキル評価値 × 1日あたりスキル発動回数
```

## 12. 1日あたりのスキル発動回数

昼は確認間隔ごと、夜は睡眠全体で抽選し、所持上限到達手伝い数を抽選可能回数の上限にします。

```text
昼区間の抽選数 = min(昼手伝い数 ÷ (確認回数 - 1), 所持上限到達手伝い数)
夜の抽選数 = min(夜手伝い数, 所持上限到達手伝い数)
```

`p` を補正スキル確率、`n` を抽選数とすると、1回も当たらない確率は次のとおりです。

```text
P(0回) = (1 - p) ^ n
P(1回) = n × p × (1 - p) ^ (n - 1)
P(2回以上) = 1 - P(0回) - P(1回)
```

- スキルとくい・オールは最大2回分を持ち越すため、0回・1回・2回以上を分けて期待回数を求めます。
- それ以外は最大1回分を持ち越すため、`1 - (1 - p) ^ n` を使用します。
- 下振れ基準では、昼の発動回数に `ProbBorder.skill()` を使用します。

## 13. ほっぺすりすりによる追加発動

トゲデマルの「ほっぺすりすり(げんきエールS)」は、自分以外から対象を選び、対象のスキルを再発動可能にします。

```text
対象選択確率 = 1 ÷ (チーム人数 - 1)

再発動可能になる確率 =
  1 - (1 - 対象ポケモンのスキル確率) ^ (実行者のスキルレベル + 1)

対象への追加発動期待回数 =
  実行者の発動回数 × 対象選択確率 × 再発動可能になる確率
```

Lv1では2回、Lv2では3回というように、抽選回数はスキルレベル+1回です。

トゲデマルが複数いる場合、追加発動したほっぺすりすりが相手を再発動させる可能性があります。現在のチームシミュレーターは、全員の通常発動回数を基準に追加分を計算し直す処理を最大10回反復し、全員の前回差が `1e-6` 未満になった時点で収束したものとして打ち切ります。これは厳密な無限連鎖ではなく期待値の近似です。

## 14. 料理

### 14.1 料理の基礎値

```text
食材素エナジー = Σ(必要食材の基礎エナジー × 必要数)
料理倍率 = マスター料理エナジー ÷ 食材素エナジー
レシピレベル適用後 = マスター料理エナジー × レシピレベル倍率
```

空き枠へ追加した食材は、その食材の基礎エナジーを加算します。

### 14.2 鍋容量

```text
鍋容量 = round(
  (基礎鍋容量 × 日曜補正 + 料理パワーアップ加算)
  × キャンプ補正
)

日曜補正 = 日曜2、それ以外1
キャンプ補正 = チケット使用時1.5、それ以外1
```

### 14.3 大成功を含む期待値

```text
大成功期待倍率 = 1 + 大成功確率 × 日曜倍率
日曜倍率 = 日曜2、それ以外1

料理エナジー =
  (レシピレベル適用後エナジー + 追加食材エナジー)
  × 大成功期待倍率
  × 設定上の料理評価倍率
```

通常の基礎大成功確率は平日0.1、日曜0.3として扱います。料理チャンスSや初期料理チャンスがある場合は、`Cooking.getChanceWeekEffect()` で週内の確率推移を計算します。

### 14.4 食材ストックの準備計算

`/food-stock` は、週替わりで選ばれる料理カテゴリごとに、同じ食材ストックから作れる料理の組み合わせを比較する。カテゴリごとに必要な食材数を求め、準備する食材数は各食材について3カテゴリの必要数の最大値とする。これは、実際にはいずれか1カテゴリだけが選ばれるためである。

```text
準備食材数[食材] = max(カレー時の必要数, サラダ時の必要数, デザート時の必要数)
バッグ使用数 = Σ 準備食材数[食材]
```

バッグ使用数が設定された食材バッグ容量以下となる組み合わせのうち、重みが0より大きいカテゴリについて次を最大化するものを選ぶ。比較は積の桁あふれを避けるため、同値な対数和で行う。

```text
最大化する値 = Π(カテゴリ合計最終エナジー ^ カテゴリ重み)
比較用の対数和 = Σ(カテゴリ重み × log(カテゴリ合計最終エナジー))
```

料理設定で有効にした料理のみを対象にし、料理設定ポップアップの「最終エナジー」（マスター料理エナジーに設定されたレシピレベル倍率を適用した値）を使用する。追加食材、大成功、フィールドボーナスは含めない。

料理の種類ごとの料理回数の上限（1～21食）と候補レシピ数はユーザーが指定する。各種類では1食以上、指定上限以下の範囲で料理数も探索し、食材バッグ容量によって上限まで作れない場合も、作成可能な回数で結果を表示する。候補は、設定した必要食材数の下限以上かつ上限以下の有効なレシピから、各種類で最終エナジーが高い順に上位n件を使用する。必要食材数の初期値は下限0・上限999で、絞り込みを行わない。組み合わせの完全総当たりは行わず、Web Workerを複数用いた多点確率探索で、レシピ構成を反復改善する。実行結果のうち最もスコアが高い実行可能解を採用するが、確率探索のため厳密な最適値を保証するものではない。

計算後の余り食材で作れる料理一覧では、食材ごとの利用可能数を「所持数 − 準備食材量 + 各食材があとX個ある場合の設定値」で求める（設定値の初期値は0）。料理に必要なすべての食材について利用可能数が必要数以上の有効レシピだけを、料理カテゴリ別に最終エナジーの高い順で表示する。

最後に、チーム全体のエナジーへ次のフィールドボーナスを掛けます。

```text
最終エナジー = ボーナス適用前エナジー × (100 + フィールドボーナス) ÷ 100
```

## 15. レベル上げ

ポケモンごとの累計必要経験値は、経験値テーブルへポケモンのEXP係数を掛けて四捨五入します。

```text
累計必要経験値 = round(EXPテーブル累計値 × ポケモンEXP係数)
```

アメ1個の経験値はレベル帯と性格で変化します。

| 使用時のレベル帯 | 上昇性格 | 補正なし | 下降性格 |
| --- | ---: | ---: | ---: |
| Lv24以下 | 47 | 40 | 33 |
| Lv25～29 | 41 | 35 | 29 |
| Lv30以上 | 30 | 25 | 21 |

各レベルで必要なアメ数は切り上げます。

```text
必要アメ数 = ceil((次レベル累計経験値 - 現在経験値) ÷ アメ1個の経験値)
必要ゆめのかけら = そのレベルのアメ単価 × 必要アメ数
```

ブースト使用時は、アメ経験値へ設定倍率、ゆめのかけらへ設定されたブースト倍率を掛けます。

## 16. 厳選スコアと厳選度

厳選の基礎スコアは1日あたりエナジーです。ゆめのかけら・リサーチEXPを評価する場合は次を加えます。

```text
ゆめのかけらボーナス込み = 基礎スコア × (1 + 0.06 × ボーナス評価率)
リサーチEXPボーナス込み = 基礎スコア × (1 + 0.09 × ボーナス評価率 ÷ 2)

最終スコア = 上記スコア
  + スキル獲得ゆめのかけら
    × ゆめのかけらのエナジー換算値
    × ボーナス評価率
```

実装上のボーナス評価率には設定値を100で割った値を使用します。

厳選度は、食材構成・サブスキル・性格の重み付きスコアを並べ、指定したパーセンタイルの位置を取得して算出します。インデックスは次の式で四捨五入します。

```text
パーセンタイル位置 = round((総重み - 1) × 現在の百分率 ÷ 100)
```

サポート系ポケモンの基準値は、設定された上位割合を抽出した後、その平均を使用します。

## 17. 計算処理を変更・利用する際の確認事項

計算式を新規利用または変更するときは、最低限次を確認してください。

- 参照するマスター値と単位が正しいか。
- サブスキルが現在レベルで解放済みか。
- 加算と乗算の順序が既存仕様と一致するか。
- `floor`、`ceil`、`round` の位置を変えていないか。
- ゲーム画面の表示値とシミュレーション内部値を混同していないか。
- チーム、厳選、概算の各モードで追加補正の有無が異ならないか。
- イベント、キャンプ、EXフィールド、睡眠リボンを二重適用していないか。
- 期待値計算と下振れ境界計算を混同していないか。
- 仕様が本文書で判断できない場合は、推測で確定せずユーザーへ確認すること。
